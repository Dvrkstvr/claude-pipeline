# Expo / React Native

## Checks
`tsc --noEmit`, `eslint`, `vitest` (plain Node) over pure `data/`-style modules,
and `npx expo export --platform <p>` for bundle-time breaks. Prefer testing pure
modules over adding a React Native test harness.

## Run & drive
- Expo Go for fast JS iteration when the SDK allows; a dev build once native
  modules are needed.
- Agent eyes: Expo MCP (SDK 54+: screenshots, UI actions, DevTools on a local
  emulator — `claude mcp add --transport http expo https://mcp.expo.dev/mcp`) or
  mobile-mcp (accessibility tree first, screenshots as fallback). `adb` for logs.
- Two-device features: a sim transport + local relay so two emulators can talk,
  with the relay able to drop/lose messages on command.

## Fakes
Native modules behind an optional bridge (`requireOptionalNativeModule` + mock)
so Expo Go degrades instead of crashing.

## Ship
`android/` / `ios/` are generated by prebuild — change config/plugins, not the
folders. Signing via a config plugin reading an uncommitted keystore file.
Package id and storage keys are addresses: renaming loses users' data.
Play: data-safety answers, permission declarations (exact alarms, foreground
service types) need written justifications.

## Docs
Read the versioned Expo docs for the project's pinned SDK before writing code
(`https://docs.expo.dev/versions/v<SDK>.0.0/`); APIs change between SDKs.
